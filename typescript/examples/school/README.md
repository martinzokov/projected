# School — a projected example

The school from Sollecito's
[*It's time to put REST to rest*](https://sollecitom.github.io/software-product-development-blog/posts/2023/2023-09-22-put-rest-to-rest/),
built with projected. Everything here is business logic; the endpoints, validation, OpenAPI
document and persistence come from the framework.

| Operation | Kind | Notes |
|---|---|---|
| `enlist-student` v1 | command | deprecated; the school picks the id |
| `enlist-student` v2 | command | the caller picks the id, so retries are safe |
| `report-student-lastname-change` v1 | command | reporting the same name is a no-op, not an error |
| `withdraw-student` v1 | command | the record is kept |
| `enlisted-students-on-joining-date` v1 | query | answered from a projection |
| `student-profile` v1 | query | a missing student is `{ "student": null }`, with 200 |

## Where things are

```
src/domain/student/             events, errors, the Student aggregate and its decisions
src/application/port/driving/   the six contracts and schoolContracts
src/application/port/driven/    StudentDirectory, the read-model port
src/application/usecase/        handlers and the student-directory projection
src/infrastructure/adapter/     StudentDirectory on any DocumentStore
src/infrastructure/config/      composeSchool (the composition root), environment (which adapters) and main (the server)
test/                           decisions (given/when/then), HTTP, access rules, retries, architecture
openapi.json                    generated by `projected openapi`
contracts.lock.json             generated by `projected contracts --update`
```

## Run it

```sh
# from typescript/
pnpm install && pnpm build
cd examples/school && SCHOOL_ADMINS=head@school.test pnpm start
```

Every operation needs a signed-in member of staff; enrolment changes need `students:manage`,
granted to better-auth admins and to the emails in `SCHOOL_ADMINS`. Sign up through better-auth's
own routes, which the service mounts at `/api/auth`:

```sh
curl -s -c jar localhost:3000/api/auth/sign-up/email -H 'content-type: application/json' \
  -H 'origin: http://localhost:3000' -d '{"email":"head@school.test","password":"correct-horse-battery","name":"Head"}'

curl -s -b jar localhost:3000/commands/enlist-student/version/2 -H 'content-type: application/json' \
  -H 'idempotency-key: enlist-bruce' \
  -d '{"studentId":"s-1","firstname":"Bruce","lastname":"Wayne","joiningDate":"2023-09-22"}'
# {"status":"ok","value":{"studentId":"s-1"}} — the same again for a retry with the same key

curl -s -b jar localhost:3000/commands -H 'content-type: application/json' -d '{"commands":[
  {"type":"report-student-lastname-change","version":1,"data":{"studentId":"s-1","newLastname":"Kent"}},
  {"type":"withdraw-student","version":1,"data":{"studentId":"s-1","leavingDate":"2024-06-30"}}]}'
# {"results":[{"status":"ok","value":{"changed":true}},{"status":"ok","value":{"withdrawn":true}}]}

curl -s localhost:3000/queries/student-profile/version/1 -H 'content-type: application/json' -d '{"studentId":"s-1"}'
# 401 — anonymous callers are turned away
curl -s localhost:3000/openapi.json
```

### On real infrastructure

```sh
docker compose up -d --wait     # from typescript/
DATABASE_URL=postgres://projected:projected@localhost:55432/projected \
KAFKA_BROKERS=localhost:9092 NATS_URL=nats://localhost:4222 \
SCHOOL_ADMINS=head@school.test pnpm start
```

Events, checkpoints, idempotency records, the student directory and better-auth's users all go
to Postgres (migrated on start); every event is also published to `school.events` on Kafka and
NATS. Register an OpenTelemetry SDK to export the traces.

## Check it

```sh
pnpm check     # projected check: architecture, contract lock, OpenAPI freshness
```

Try breaking a rule — import `node:fs` in `src/domain`, add a field to a published contract,
call `Date.now()` in a use case — and watch `tsc -b` or `projected check` refuse it.
